---
name: creating-pdf-reports
description: Produces professional, accessible PDF reports with data-driven charts, rendered and validated locally with open-source tools (Typst, matplotlib, veraPDF). Use when the user asks for a PDF report, whitepaper, or printable document; when a workflow's findings or analysis must be delivered as a PDF; when data needs charts embedded in a document; or when existing markdown or HTML content must become a polished PDF.
---

The defining rule: you plan, write, and explain; only validated source
data and deterministic rendering assert what the data says. Every number
in the report (prose, chart, or table) is copied from a data source that
exists on disk, and every chart is generated by the bundled script from
a spec, never drawn or described from memory.

Everything runs locally with OSS tools: Typst (renderer), matplotlib and
pypdf (via uv, automatic), veraPDF and WeasyPrint when needed. The
report's content stays on this machine, so rendering and validation use
these tools only; online converters and document-generation APIs are off
limits even when they would be faster.

`scripts/`, `references/`, and `assets/` paths below are relative to
this skill's directory.

## Step 1 — Scope

Establish before writing anything:

- Audience and purpose: who reads this, and what decision or question
  does it serve?
- Locale: `en` or `it` (the theme and writing rules handle both).
- Conformance: does the user or context require accessibility (PDF/UA)
  or archival (PDF/A)? Public-sector or compliance contexts usually do;
  otherwise the default profile is fine.
- Claims inventory: list every claim the report will make, each mapped
  to a data source on disk (file path, extract, or query result). A
  claim with no source is either backed by data you obtain now or cut.

Done when: a section outline exists in which each section names the
question it answers, and each planned claim has a source path.

## Step 2 — Tooling

Verify `typst --version` and `uv --version`. Install what is missing:
`brew install typst` on macOS (Linux: distro package or the GitHub
release binary); uv installs the Python script dependencies on first
run by itself. Add `brew install verapdf` only when Step 1 set a PDF/A
or PDF/UA requirement.

Done when: `typst --version` succeeds.

## Step 3 — Figures

Read [references/figure-specs.md](references/figure-specs.md) now if the
report contains any chart. For each figure write a spec YAML (question,
takeaway, data, encodings, source note, alt text), then render it:

```sh
uv run scripts/make_chart.py fig-name.yaml
```

Fix the named validation errors until it outputs the SVG. A stderr
warning is a design question (too many series, grouped bars): answer it
by changing the figure design or by recording the reason to keep it.

Done when: every figure in the outline has a spec file and a
script-generated SVG, and no warning is left unaddressed.

## Step 4 — Compose

Copy `assets/report-theme.typ` and `assets/report-starter.typ` into the
working directory, rename the starter, and replace its content. The
starter demonstrates every pattern once (title block, summary, figure,
table, callout); the theme fixes tokens, typography, and layout, so
composition is about content and order, not styling.

Read [references/design-rules.md](references/design-rules.md) before
writing the prose: it sets the figure-selection, truthful-encoding,
layout, and plain-language rules (English and Italian) the report is
reviewed against.

If the content already exists as HTML/CSS, render it with WeasyPrint
instead: follow [references/weasyprint.md](references/weasyprint.md)
for this step, then continue with Step 5.

Done when: the report compiles without warnings, every figure and table
is cited from the prose, and every number in the prose traces to the
Step 1 claims inventory.

## Step 5 — Validate

Follow [references/pdf-standards.md](references/pdf-standards.md): pick
the compile flags from the Step 1 conformance answer, then run the three
gates in order — `uv run scripts/check_pdf.py report.pdf` (baseline,
must reach 0 failures), veraPDF (only for PDF/A or PDF/UA claims), and
visual inspection of rendered page images (actually look at them:
overflow, orphaned headings, unreadable chart text).

Done when: the checker reports 0 failures, any conformance claim is
veraPDF-validated, and every page has been looked at.

## Step 6 — Deliver

Hand over the PDF path with: the validation results, the reason for any
remaining warning or rule deviation, and the source for each figure.
State that automated checks passed but factual sign-off and
assistive-technology testing need a human reviewer; the pipeline cannot
certify its own truthfulness.
