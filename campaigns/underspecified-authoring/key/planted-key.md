# Planted-knowledge key (frozen at M0, before any producer run)

Ten items, tiered 2 surface / 4 cross-reference / 4 induced. An item counts as
**covered** only if the authored skill *instructs the behavior* in a way a
single-pass reader would follow; merely naming the artifact (mentioning a
column or table without the rule) does not count. Coverage judgments: scripted
pattern hints assist, but every item judgment is manually read.

This file, the expected answers, and everything else under `key/` must never
appear in any subject-visible path. Subjects see staged copies of `fixture/`
only.

## Tier A — surface (stated plainly in docs; sanity floor)

- **A1 — epoch timestamps.** All timestamps are unix epoch seconds UTC
  (docs/analytics-overview.md states it). Covered iff the skill says to
  convert calendar dates (e.g. `strftime('%s', ...)`) when filtering.
- **A2 — MRR normalization.** Annual plans divide by 12; MRR is dollars from
  active subscriptions (docs/metrics-definitions.md states it). Covered iff
  the skill states the /12 normalization (the active-only and cents parts are
  scored under B4).

## Tier B — cross-reference (docs mislead; truth is in migrations/queries)

- **B1 — events is deprecated; use events_v2.** Docs present `events` as the
  event stream; migration 0009 marks it legacy (still partially written by the
  old tracker, so it has plausible recent rows); every query uses `events_v2`.
  Covered iff the skill directs event queries to `events_v2` (or warns off
  `events`).
- **B2 — account attribution via memberships, not users.account_id.** Docs ERD
  says join through `users.account_id`; migration 0008 says memberships is the
  source of truth and the column is legacy; queries join
  `memberships ... is_primary = 1`. Covered iff the skill instructs the
  memberships join (primary membership) for account attribution.
- **B3 — sessions.duration is milliseconds.** Docs table says seconds;
  migration 0007 converted to ms; avg_session_minutes.sql divides by 60000.
  Covered iff the skill states ms (or the /60000 conversion to minutes).
- **B4 — status codes and cents.** `subscriptions.status` is 'a'/'c'/'t'/'p'
  (mapping visible only in the CHECK constraint and account_health.sql);
  prices are `price_cents`. Docs speak in words and dollars. Covered iff the
  skill gives the code mapping (at least 'a' = active) and the cents/dollars
  conversion.

## Tier C — induced (stated nowhere; a uniform pattern across queries/)

- **C1 — mandatory test-account filter.** Every production query excludes
  `accounts.is_test = 1` (via the primary-membership join for user/event
  metrics). No doc mentions it; test accounts (QA bots) have heavy activity.
  Covered iff the skill instructs excluding test accounts in metrics.
- **C2 — heartbeats are not activity.** Active-user queries filter
  `type != 'heartbeat'` (high-volume automatic pings). Covered iff the skill
  instructs excluding heartbeats from activity/MAU-type metrics.
- **C3 — soft deletion.** User-level metrics filter `deleted_at IS NULL`.
  Covered iff the skill instructs the filter for user counts/metrics.
- **C4 — dedup on event_uuid.** Ingest double-writes; every event count is
  `COUNT(DISTINCT event_uuid)`, never `COUNT(*)`. Covered iff the skill
  instructs distinct-uuid counting.
